## TypeSafe AI Jev

The identity is verified through [TypeSafe's own introduction](https://docs.typesafe.ai/introduction), reached from its [company site](https://typesafe.ai/): Jev is its flagship System One decision model, rather than a scikit-learn estimator. Its typed decisions make a four-class routing comparison technically plausible; routing performance remains unmeasured.

The official [model reference](https://docs.typesafe.ai/models) lists `jev-1.14.0` (available October 14, 2026) and `jev-1.13.0`. Both accept natural-language text; English is the primary training language. Current `jev-latest` and `jev-preview` aliases point to 1.14 but can move. Pin a version and log the returned model ID. Default limits are 64k tokens per request and 32k per question. Pricing is $0.042 per million input tokens, with output tokens free. Limits depend on the organization. No local weight distribution or local inference license was established from these documents; local execution must remain unverified. Jev uses shared weights, with domain rules supplied in requests rather than customer fine-tuning.

The [API reference](https://docs.typesafe.ai/api/system-one) specifies `POST https://api.typesafe.ai/v1/systemone` with bearer authentication, `model`, `state` (string/object/array), and named `questions`. It returns answers, model identity and token usage. The [quick start](https://docs.typesafe.ai/introduction/quickstart) directs users to obtain a console API key and supports direct HTTP or SDK access. Actual account eligibility, credits, access and organization limits were not tested.

A proposed adapter would place exactly one unchanged query in `state`, ask one [Choice](https://docs.typesafe.ai/primitives/choice) question about the earliest necessary action, and use the four protocol labels as criteria keys with their operational definitions. Choice returns the selected option, a probability per option and `confidence`. This is a pretrained model prompted with schema/rules, whereas TF-IDF classifiers learn vocabulary and weights from this study's training rows. Report it as a distinct comparison condition, including unknown pretraining overlap. Do not supply attachments, source IDs, annotation rationales, expected labels or upstream task metadata as query context. Any examples must come from training only; bound prompt candidates in advance, select using validation only, and freeze prompt bytes, option order, model ID and response handling before final test access.

The [confidence documentation](https://docs.typesafe.ai/confidence) describes `confidence` as a statistic of the option distribution. It is not interchangeable with the maximum class probability or empirical accuracy. Preserve all four probabilities in the fixed class order, keep the vendor statistic separately, and measure calibration on this task before making calibration claims. Structured valid output establishes schema compliance, not semantic correctness.

The [legal index](https://docs.typesafe.ai/legal) links its customer agreement, DPA and privacy policy, says customer data is not used for training, and offers enterprise zero data retention. This does not establish default zero retention, an open model license, or permission to upload this corpus. Before implementation calls: verify applicable service terms, source permissions and data handling; obtain explicit external-processing and paid-service authorization with a spending cap. Estimate cost from actual input-token usage including repeated instructions, examples, retries and reruns. Do not infer free access from low published pricing. No such authorization is supplied by this note.
